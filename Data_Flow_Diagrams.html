Context Boundary Analysis

The Level 0 Context Diagram establishes the formal boundaries of the UrbanHeliX platform. The system operates as a zero-trust black box that interacts with four main human stakeholders and three external programmatic interfaces.

External Entity Flows

  • Citizens Submit grievance reports (issue details, photo evidence, coordinates) and retrieve transparent dashboards on project execution and public fund utilization.
  • Contractors Provide project bids, milestone completions with embedded GPS-enforced photo proofs, and invoices. They receive status clearances and processed fund disbursements.
  • Engineers Deploy project plans, review milestone uploads, and execute inspection checklists. They receive action assignments and real-time security anomalies.
  • Financial Authorities Allocate budgets across city areas/wards and sign off payment milestones. They receive verified expense tracking and tamper-chain audit logs.

Functional Core Breakdown

The Level 1 Diagram breaks down the platform into 6 core operational processes and maps their specific interactions with structural database and file stores.

Data Stores

  • D1: MongoDB Atlas (Relational-JSON) Stores active user schemas, ward funding nodes, milestones parameters, audit traces, and cryptographic chain logs.
  • D2: AWS S3 Object Storage Retains structural files including bills (PDF format), GPS-locked evidence photos, and citizen grievance image streams.
  • D3: Blockchain Ledger (Ethereum/Hardhat Smart Contracts) Decentralized ledger containing immutable milestone hash receipts, financial disbursement approvals, and department budget checkpoints.
🛡️
Cryptographic Auditing (Process 6.0) operates continuously in the background, auditing MongoDB collections using a block-level HashChain structure, generating a real-time defense against backend intrusions.

Sub-System Process Explosion

Decomposes Process 3.0 (Milestone & GPS Verification) into technical child steps that establish evidence authentication and decentralized recording.

Step-by-Step Flow Analysis

  • 3.1 EXIF Extraction Extracts geolocation metadata from EXIF headers inside images uploaded by contractors.
  • 3.2 Geo-fencing Audit Fetches target coordinates from MongoDB. Calculates distance using the Haversine formula, automatically rejecting the upload if coordinates deviate beyond 50m.
  • 3.3 AWS S3 Streams Streams verified media to AWS S3, obtaining a secure public URL.
  • 3.4 & 3.5 Aadhaar OTP Sign-off & Blockchain Notarization Engineers review photos and verify the milestones. High-value approvals mandate Aadhaar KYC validation. On success, Ethers.js generates a transaction payload, deploying the block permanently to D3.
  • 3.6 WebSocket Synchronization Saves transaction block data to MongoDB (D1) and notifies active web clients via Socket.io.

Sub-System Process Explosion

Decomposes Process 6.0 (HashChain Auditing) to demonstrate how UrbanHeliX enforces high-performance, real-time database intrusion detection.

Step-by-Step Flow Analysis

  • 6.1 Write Hook & Hash Generation Backend middleware triggers on mutations. Chains the new entry to the previous record's SHA-256 hash, saving the cryptographic chain block in the MongoDB collection `hashchainrecords`.
  • 6.2 Background Audit Daemon A background process polls the MongoDB store every 10 seconds, recalculating hashes from genesis forward to detect unauthorized updates.
  • 6.3 Tamper Locator Pinpoints exact indices containing modified parameters. Logs details immediately to `auditlogs`.
  • 6.4 & 6.5 Real-time Alarm Systems Instantly broadcasts alert packets to active dashboards (via Socket.io) and pushes high-priority payloads to Firebase Cloud Messaging to alert off-duty officers.
